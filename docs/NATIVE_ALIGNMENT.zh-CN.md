# v0.5 原版行为、开源参考与新地图

本地基准为 **Minecraft Java 1.21**。起床战争是服务器插件玩法，没有一份 Minecraft 官方统一的商店和复活规则。原生行为与本赛项扩展均写入 `competition/rules.json`，网页直接显示由它生成的规则文档；游戏内 `/localbw rules` 打开原版书本界面的规则书。

## 修正内容

- 网页物品按官方 `generated` / `handheld` 模型继承、贴图分层和 `display` 参数生成；剑、食物、方块和弓不再共用一张随意旋转的平面。物品边缘按纹理轮廓生成厚度，药水只给药液层着色。
- 弓的视觉拉弦阶段按官方模型的 `0.65` / `0.9` 阈值选择，即满蓄力 20 刻中的第 13 / 18 刻。吃、喝、拉弓和瞬时投掷分别处理。
- 记录服务器真实的使用动作、已使用/剩余刻数、手持物元数据、眼高、身体朝向、挥手起始刻和持续时间。游戏时钟逐刻计数，状态记录与观战流为 10 Hz。
- 摆臂、身体转动与持握坐标修正到对应的模型空间。第一视角拿物品时显示物品模型，空手时才显示手臂；不再始终附加一只错误的大手臂。
- TNT、珍珠、火球和箭使用官方纹理。TNT 闪烁由记录的引信驱动，暂停回放时不会继续按墙钟闪动。水桶、流体变化、海绵吸水和火焰变化也写入回放。
- 实服检查确认金苹果与药水使用时间为 32 刻；金苹果产生 4 点吸收生命；迅捷药水为本赛项配置的速度 II、45 秒，喝完会留下玻璃瓶。
- 修复 SBW 0.2.44 在当前 Paper 版本上将自己珍珠的伤害纳入友伤取消的问题。兼容层只恢复自己珍珠的原生伤害事件，并保留出生保护。实测无保护、无吸收时生命从 20 降到 15。Paper 暴露的 Bukkit 事件类别为 `PROJECTILE`，不能仅凭事件名把它认作没有珍珠伤害。
- AI 选择高地时会保持合法可见范围；使用弓时考虑可见目标移动和箭下坠；近战按眼睛到目标碰撞箱的距离处理高低差。听到自己床附近实际收到的破坏音效时可以检查威胁。
- AI 不再把原版隐身当成盔甲也消失，不再忽略眼前守卫；进攻珍珠需留出自身受伤余量。末影箱访问按原版玩家身份共享，不会因为站在对方基地就误认为取不出自己的储备。

## 地图

`sky-harbor-3.0` 位于独立世界 `bedwars-v5`。两个旧世界及其回放快照保留。

- 对称基地：商店长廊、资源区、普通箱/末影箱、带台阶的屋顶射击位置。
- 中央岛：上下两层廊道、可通行的下层、楼梯与掩体；主要进攻桥仍需玩家搭建。
- 两座对称钻石侧岛：可以选择经济路线、回防或从侧面接近中心。
- 高地和掩体坐标是公开地图信息，双方策略使用同一套移动规则。原始地图受保护，玩家搭建仍按真实方块处理。

## 怎样观看与验证

双击根目录 **原版观战.cmd** 打开未修改的 Java 1.21 客户端，连接本机测试服并以旁观者跟随示例 AI。它与无图形 AI 控制进程分开，真实的界面、动画、粒子和声音由 Minecraft 自己绘制。Shift 可退出跟随，F5 切换视角。

网页 `http://127.0.0.1:3007/` 保留平视跟随和完整回放。网页是重建画面；需要完全原版画面时以原版客户端为准。

`runs/showcase-v5/native-verification.json` 记录标为 test 的实服核对，包括实际上下楼梯、搭桥、主动选择高地、蓄力箭命中、食物/药水、珍珠、水和 TNT。它与正常比赛记录分开。该报告不是高手胜率证明；示例仍是已有小模型与公开策略的混合控制器，AGX 正式执行器与预算隔离仍待后端接入。
